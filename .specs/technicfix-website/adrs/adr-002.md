# ADR-002: Banco de Dados — PostgreSQL + Prisma

## Status

Aceito

## Data

2026-07-01

## Contexto

O site precisa de persistência para produtos, categorias, banners, leads e configurações. A opção SQLite era viável em VPS mas incompatível com Vercel serverless. Precisamos de um banco serverless-friendly, com suporte a Prisma ORM para manter a camada de persistência abstraída e facilitar migração futura.

## Decisão

Usar **PostgreSQL gerenciado (Neon free tier)** como banco de dados, com **Prisma ORM** como camada de acesso a dados. A string de conexão será injetada via variável de ambiente (`DATABASE_URL`), mantendo o código agnóstico ao provedor.

## Alternativas Consideradas

### Alternativa 1: SQLite + Prisma

- **Descrição**: Banco de arquivo local, zero custo de infraestrutura
- **Prós**: Sem configuração de servidor, zero custo, rápido para desenvolvimento local
- **Contras**: Não funciona em ambiente serverless (Vercel); cada função cria uma nova conexão sem estado compartilhado
- **Por que rejeitada**: Incompatível com Vercel (deploy alvo escolhido)

### Alternativa 2: PlanetScale (MySQL) + Prisma

- **Descrição**: MySQL serverless gerenciado com branching de schema
- **Prós**: Bom free tier, schema migrations via branches
- **Contras**: PlanetScale encerrou o plano gratuito em 2024; custo mínimo de $39/mês
- **Por que rejeitada**: Custo inviável para MVP de pequeno porte

## Consequências

### Positivas

- Prisma abstrai o provider: migrar de Neon para Supabase ou RDS exige apenas trocar a `DATABASE_URL`
- PostgreSQL suporta todos os padrões de query necessários para Fase 3 (e-commerce)
- Neon oferece conexão serverless nativa (connection pooling via Neon Serverless Driver)

### Negativas

- Requer configuração de conta no Neon e criação do banco antes do primeiro deploy
- Migrations devem ser aplicadas manualmente ou via CI/CD (`prisma migrate deploy`)

### Riscos

- Limite de storage do Neon free tier (0.5 GB): suficiente para o MVP, mas monitorar crescimento de imagens no banco (mitigado pelo uso de R2 para arquivos binários)

## Notas de Implementação

- Usar `@prisma/client` com `prisma generate` no build step do Vercel
- Configurar `DATABASE_URL` e `DIRECT_URL` (para migrations) como variáveis de ambiente no Vercel
- Usar Neon Serverless Driver (`@neondatabase/serverless`) para connection pooling em funções serverless
