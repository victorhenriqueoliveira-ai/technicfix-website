# ADR-003: Storage de Imagens — Cloudflare R2

## Status

Aceito

## Data

2026-07-01

## Contexto

O painel admin precisa de upload de imagens para produtos (múltiplas fotos por produto) e banners. As imagens precisam ser servidas com baixa latência global e otimizadas via `next/image`. O storage não pode ser o sistema de arquivos local (incompatível com Vercel serverless).

## Decisão

Usar **Cloudflare R2** como object storage para imagens, acessado via SDK compatível com AWS S3. As URLs públicas dos objetos serão servidas via domínio público do bucket R2 e passadas para `next/image` com o domínio configurado em `next.config.ts`.

## Alternativas Consideradas

### Alternativa 1: AWS S3

- **Descrição**: Object storage padrão de mercado da Amazon
- **Prós**: Amplamente documentado, ecossistema maduro
- **Contras**: Custo de egress (saída de dados) por GB transferido; requer conta AWS com cartão de crédito
- **Por que rejeitada**: Custo de egress penaliza sites com muitas imagens; R2 é S3-compatível sem egress

### Alternativa 2: Uploadthing

- **Descrição**: SDK de upload nativo para Next.js App Router
- **Prós**: DX excelente, integração com Server Actions, free tier de 2GB
- **Contras**: Free tier pequeno (2GB); custo após isso; cria dependência de vendor para funcionalidade crítica
- **Por que rejeitada**: R2 oferece 10GB free e é portátil (S3-compatível)

## Consequências

### Positivas

- 10GB de storage gratuito, sem custo de egress — ideal para MVP
- API S3-compatível: uso do AWS SDK v3 padrão sem lock-in
- Integração nativa com Cloudflare CDN para baixa latência global

### Negativas

- Requer configuração de bucket R2, chave de API e domínio público no Cloudflare
- Upload de imagens no admin requer Server Action ou API Route intermediária (não upload direto do browser para R2 sem signed URL)

### Riscos

- Configuração de CORS no bucket R2 necessária para upload via browser com presigned URLs
- Domínio público do R2 precisa ser adicionado a `images.remotePatterns` no `next.config.ts`

## Notas de Implementação

- Usar `@aws-sdk/client-s3` com endpoint apontando para `https://<account>.r2.cloudflarestorage.com`
- Gerar presigned PUT URL no servidor para upload direto do browser (evita tráfego pelo Vercel)
- Nomear objetos com UUID + extensão original para evitar colisões: `products/{uuid}.webp`
