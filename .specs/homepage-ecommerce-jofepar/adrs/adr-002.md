# ADR-002: Hierarquia de Categorias via parentId Auto-referencial no Prisma

## Status

Aceito

## Data

2026-07-15

## Contexto

O modelo `Category` atual é flat (sem hierarquia). O mega-dropdown do nav requer categorias-pai e subcategorias. Duas abordagens foram consideradas para modelar a hierarquia.

## Decisão

Adicionar `parentId String?` ao modelo `Category` com relação auto-referencial Prisma (`parent` e `children`). Uma categoria sem parentId é raiz (aparece no nav); com parentId é filha (aparece no dropdown do pai). Migração: `npx prisma migrate dev --name add_category_parent`.

```prisma
model Category {
  id        String     @id @default(cuid())
  name      String
  slug      String     @unique
  imageUrl  String?
  parentId  String?
  parent    Category?  @relation("CategoryChildren", fields: [parentId], references: [id])
  children  Category[] @relation("CategoryChildren")
  products  Product[]
  createdAt DateTime   @default(now())
  updatedAt DateTime   @updatedAt
}
```

## Alternativas Consideradas

### Alternativa: Tabela separada CategoryGroup

- **Descrição**: Nova tabela `CategoryGroup` com relação 1:N para Category.
- **Prós**: Separação clara entre grupos e categorias.
- **Contras**: Adiciona um model extra sem ganho real para este caso de uso de 2 níveis.
- **Por que rejeitada**: YAGNI — dois níveis resolvem o problema com a menor mudança possível.

## Consequências

### Positivas

- Permite hierarquia de 2 níveis sem tabela extra.
- Query Prisma simples: `findMany({ where: { parentId: null }, include: { children: true } })`.
- Admin pode criar pai/filho com campo select de parentId.

### Negativas

- parentId nullable cria categoria "órfã" se pai for deletado — mitigar com cascade ou validação no admin.
- Hierarquia limitada a 2 níveis — suficiente para o escopo atual.

### Riscos

- Deleção de categoria-pai: implementar validação em `deleteCategory` para bloquear se tiver filhos.

## Notas de Implementação

- `actions/categories.ts`: adicionar campo `parentId` opcional ao schema Zod de createCategory/updateCategory.
- `deleteCategory`: verificar se `children.length > 0` antes de deletar.
- `lib/types.ts`: adicionar `CategorySummary` com `children: CategorySummary[]`.
