# ADR-003: Propagação do Campo Badge via page.tsx (Restrição Relaxada)

## Status

Aceito

## Data

2026-07-15

## Contexto

O PRD restringia alterações em `app/(public)/page.tsx` para preservar a lógica de fetch existente. Contudo, o campo `badge` adicionado ao modelo `Product` precisa ser incluído na query `getFeaturedProducts` e tipado em `ProductSummary` para chegar ao componente `FeaturedProducts`. Da mesma forma, os pill badges dinâmicos da hero precisam dos campos `heroBadge1`/`heroBadge2` do `SiteConfig`, que já é buscado em `page.tsx`, mas cujos novos campos precisam ser propagados como props para `<Hero>`.

## Decisão

Relaxar pontualmente a restrição de `page.tsx` para:
1. Adicionar `badge: true` ao `include` de `getFeaturedProducts` (sem alterar a lógica de busca).
2. Passar `heroBadge1` e `heroBadge2` como props para `<Hero banners={banners} heroBadge1={config.heroBadge1} heroBadge2={config.heroBadge2} />`.
3. Remover o import e uso de `TestimonialsSection` (ver ADR-002).

A lógica de orchestração, tipagem de retorno e estrutura de `Promise.all` em `page.tsx` não são alteradas.

## Alternativas Consideradas

### Alternativa 1: FeaturedProducts faz fetch próprio de BD

- **Descrição**: Tornar `FeaturedProducts` um Server Component com seu próprio `db.product.findMany`.
- **Prós**: `page.tsx` não muda.
- **Contras**: Fetch paralelo extra, duplicação de lógica, foge do padrão existente do projeto (todos os fetches centralizados em `page.tsx`).
- **Por que rejeitada**: O padrão do projeto é centralizar fetches na Server Component de página; duplicar vai contra esse padrão e traz overhead desnecessário.

## Consequências

### Positivas

- Mantém o padrão de fetch centralizado em `page.tsx`.
- Alterações em `page.tsx` são mínimas e cirúrgicas (3 linhas efetivas).

### Negativas

- Viola formalmente a restrição do PRD de "não alterar page.tsx" — mas de forma acordada e documentada.

### Riscos

- Nenhum risco de regressão: a alteração é aditiva (campos opcionais nullable), não modifica comportamento existente.

## Notas de Implementação

- Em `lib/types.ts`: adicionar `badge: string | null` a `ProductSummary` e `heroBadge1: string | null`, `heroBadge2: string | null` a `SiteConfig`.
- Em `page.tsx`: no mapeamento de `ProductRow → ProductSummary`, incluir `badge: p.badge ?? null`.
- Em `page.tsx` JSX: `<Hero banners={banners} heroBadge1={config.heroBadge1 ?? null} heroBadge2={config.heroBadge2 ?? null} />`.
