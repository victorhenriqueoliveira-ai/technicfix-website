# ADR-005: SiteConfig como fonte única do número de WhatsApp nos CTAs de produto

## Status

Aceito

## Data

2026-07-01

## Contexto

O número de WhatsApp existe em dois lugares: `SiteConfig.whatsappNumber` (banco de dados, editável pelo admin) e `NEXT_PUBLIC_WHATSAPP_NUMBER` (variável de ambiente, usada pelo `WhatsAppButton` flutuante global). Os CTAs da página de produto precisam gerar links `wa.me` com o número correto. É necessário definir qual fonte usar.

## Decisão

Ler `SiteConfig.whatsappNumber` no Server Component `ProductPage` e passar o número como prop para `ProductCTAs`. O `WhatsAppButton` flutuante continua usando `NEXT_PUBLIC_WHATSAPP_NUMBER` por ora (fora do escopo deste PRD); a unificação completa fica para trabalho futuro.

## Alternativas Consideradas

### Alternativa 1: Variável de ambiente (NEXT_PUBLIC_WHATSAPP_NUMBER)

- **Descrição**: Usar a env var já existente nos CTAs de produto, sem query extra ao banco.
- **Prós**: Zero query adicional na página de produto; valor disponível no cliente sem prop drilling.
- **Contras**: Número só muda com redeploy; admin não pode alterar pelo painel — contradiz o requisito do PRD.
- **Por que rejeitada**: Viola o requisito explícito de que o número é gerenciado pelo admin via SiteConfig.

### Alternativa 2: Unificar completamente (migrar WhatsAppButton para SiteConfig também)

- **Descrição**: Remover `NEXT_PUBLIC_WHATSAPP_NUMBER`; todos os componentes leem de `SiteConfig`.
- **Prós**: Fonte única de verdade em todo o projeto; sem inconsistência futura.
- **Contras**: Escopo adicional; `WhatsAppButton` é componente global que pode precisar de refatoração mais cuidadosa.
- **Por que rejeitada**: Fora do escopo deste PRD; pode ser feito como tarefa de limpeza separada.

## Consequências

### Positivas

- Admin controla o número pelo painel sem redeploy.
- `ProductPage` já busca o produto com `db.product.findFirst`; adicionar `db.siteConfig.findUnique` no mesmo Server Component é custo mínimo.

### Negativas

- Inconsistência temporária: `WhatsAppButton` usa env var, CTAs de produto usam banco. Documentada como dívida técnica.
- Se `SiteConfig.whatsappNumber` estiver vazio, os botões de WhatsApp não devem ser renderizados — requer guard no componente.

### Riscos

- Cache: `ProductPage` tem `export const dynamic = 'force-dynamic'`, então o número sempre virá atualizado do banco.
