# ADR-004: Nova model Sale separada para registro de vendas

## Status

Aceito

## Data

2026-07-01

## Contexto

O módulo de Vendas (PRD F6) precisa registrar vendas com productId, quantity, buyerType, notes e createdAt. Duas opções foram avaliadas: criar uma nova model `Sale` ou reutilizar o model `Lead` existente adicionando campos de venda.

## Decisão

Criar nova model `Sale` no schema Prisma com campos: `id`, `productId` (FK obrigatória), `quantity` (Int), `buyerType` (enum LeadType), `notes` (String?), `createdAt`. A migration adiciona a tabela `Sale` e uma relação `Product.sales` para permitir agregações de vendas por produto.

## Alternativas Consideradas

### Alternativa 1: Reutilizar Lead com campos extras

- **Descrição**: Adicionar `saleQuantity Int?` e `saleDate DateTime?` ao model `Lead` existente; vendas seriam leads com `status = 'convertido'`.
- **Prós**: Zero nova tabela; sem migration complexa.
- **Contras**: Mistura semântica — um lead pode existir sem virar venda, e uma venda registrada manualmente não é necessariamente um lead; campos nullable poluem o model; queries de agregação precisam de filtros extras frágeis.
- **Por que rejeitada**: Viola separação de responsabilidades; tornaria queries de dashboard mais complexas e propensas a erro.

## Consequências

### Positivas

- Schema limpo com separação clara entre captura de interesse (Lead) e registro de transação (Sale).
- Queries de dashboard (`groupBy`, `aggregate`) diretas e sem filtros extras.
- Relacionamento `Product → Sales` facilita cálculo de top produtos.

### Negativas

- Requer nova migration Prisma.
- Uma venda manual não cria automaticamente um lead (os dois são independentes).

### Riscos

- Concorrência: dois registros simultâneos de venda para o mesmo produto podem gerar estoque negativo se não houver transação. Mitigar com `db.$transaction` no `registerSale`.

## Notas de Implementação

```prisma
model Sale {
  id        String    @id @default(cuid())
  product   Product   @relation(fields: [productId], references: [id])
  productId String
  quantity  Int
  buyerType LeadType
  notes     String?
  createdAt DateTime  @default(now())
}
```

Adicionar `sales Sale[]` ao model `Product`.
