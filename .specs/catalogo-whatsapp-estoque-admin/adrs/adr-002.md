# ADR-002: Resend como provedor de e-mail para notificações de lead

## Status

Aceito

## Data

2026-07-01

## Contexto

O projeto não tem nenhuma biblioteca de e-mail instalada. A feature F4 (formulário de lead inline) exige envio de e-mail de notificação ao responsável da loja quando um lead é submetido. É necessário escolher um provedor compatível com Next.js App Router e Server Actions.

## Decisão

Usar Resend (`resend` SDK) como provedor de e-mail. O e-mail de destino é lido de `SiteConfig.contactEmail`. O envio ocorre dentro da Server Action `submitLead`, após o lead ser persistido no banco.

## Alternativas Consideradas

### Alternativa 1: Nodemailer + SMTP

- **Descrição**: Biblioteca Node.js clássica de envio de e-mail via SMTP (Gmail, Zoho, servidor próprio).
- **Prós**: Sem custo de API; funciona com qualquer servidor SMTP existente.
- **Contras**: Configuração mais verbosa; problemas conhecidos com Edge Runtime e ambientes serverless; credenciais SMTP sensíveis precisam de configuração adicional.
- **Por que rejeitada**: Maior fricção de setup e risco de incompatibilidade com o ambiente serverless (Neon + Next.js).

### Alternativa 2: Sem e-mail na Fase 1

- **Descrição**: Lead salvo no banco; notificação por e-mail adiada para fase futura.
- **Prós**: Zero dependência nova na Fase 1.
- **Contras**: Operador não é notificado em tempo real de novos leads — derrota parte do valor da feature.
- **Por que rejeitada**: A notificação foi explicitamente definida como parte do MVP (F4).

## Consequências

### Positivas

- SDK TypeScript nativo; integração direta com Server Actions em 5-10 linhas.
- Plano gratuito cobre até 3.000 e-mails/mês — suficiente para o volume esperado.
- Sem problemas de compatibilidade com ambiente serverless.

### Negativas

- Dependência de serviço externo pago (acima do free tier).
- Requer configuração de domínio verificado no Resend para evitar cair em spam.

### Riscos

- Se `RESEND_API_KEY` não estiver configurada no ambiente, o envio falha silenciosamente — mitigar com log de erro e retorno de `{ success: true }` mesmo sem e-mail (o lead já foi salvo).
