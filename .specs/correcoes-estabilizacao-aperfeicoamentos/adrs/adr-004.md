# ADR-004: Carrossel de produtos relacionados via CSS scroll snap

## Status

Aceito

## Data

2026-07-17

## Contexto

O componente `RelatedProducts` atual renderiza produtos relacionados em grid de 4 colunas como Server Component. O PRD F8 requer conversão para carrossel horizontal com scroll. As opções foram: CSS scroll snap nativo (sem nova dependência, RSC mantido), Client Component com `useRef` + `scrollBy()`, ou biblioteca de carrossel como Embla.

## Decisão

Converter o container de grid para `flex overflow-x-auto scroll-smooth snap-x snap-mandatory` com `scroll-snap-align: start` em cada card. O componente permanece Server Component (sem hydration extra). Cards têm largura fixa responsiva (`w-52 sm:w-60`) para criar o efeito de peek do próximo card. Nenhuma nova dependência é adicionada.

## Alternativas Consideradas

### Alternativa B: Client Component com useRef + scrollBy()

- **Descrição**: Transformar `RelatedProducts` em Client Component com botões prev/next que chamam `ref.current.scrollBy()`.
- **Prós**: Controle preciso de scroll; botões de navegação explícitos para mouse/desktop.
- **Contras**: Adiciona hydration ao componente (bundle JS client); botões prev/next requerem lógica de visibilidade.
- **Por que rejeitada**: CSS scroll snap com scroll nativo do navegador funciona igual ou melhor em touch (mobile-first), e o componente permanece Server Component.

### Alternativa C: Biblioteca Embla Carousel

- **Descrição**: Instalar `embla-carousel-react` (~7kb gzipped) para gerenciar o carrossel.
- **Prós**: Recursos extras (loop, autoplay, lazy load por slide).
- **Contras**: Nova dependência; obriga Client Component; funcionalidades extras não são necessárias para este caso.
- **Por que rejeitada**: Overkill para um carrossel simples; viola YAGNI.

## Consequências

### Positivas

- Zero nova dependência.
- `RelatedProducts` permanece Server Component — sem JS adicional no cliente.
- Scroll nativo = suporte perfeito a touch em mobile sem nenhum código JS.
- `::-webkit-scrollbar { display: none }` via Tailwind (`scrollbar-hide`) elimina barra de scroll visualmente.

### Negativas

- Sem botões de navegação explícitos para mouse em desktop — usuários desktop precisam de scroll horizontal (dois dedos no trackpad ou scroll horizontal com shift+scroll). Considerado aceitável dado que a maioria do tráfego é mobile.
- Scroll snap em Safari pode ter comportamento ligeiramente diferente; testar em iOS.

### Riscos

- Se Tailwind v4 não tiver a utilitária `scrollbar-hide` built-in, é necessário CSS personalizado ou plugin. Mitigação: adicionar `overflow-x: scroll; scrollbar-width: none` via `@layer utilities` se necessário.

## Notas de Implementação

```tsx
// RelatedProducts.tsx — estrutura do container
<div className="flex gap-4 overflow-x-auto scroll-smooth snap-x snap-mandatory pb-2
                [&::-webkit-scrollbar]:hidden [-ms-overflow-style:none] [scrollbar-width:none]">
  {products.map((p) => (
    <div key={p.id} className="w-52 sm:w-60 flex-none snap-start">
      <ProductCard product={p} />
    </div>
  ))}
</div>
```
