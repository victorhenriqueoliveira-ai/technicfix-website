# ADR-003: Componente Slider de preço via @base-ui/react

## Status

Aceito

## Data

2026-07-17

## Contexto

O filtro de preço do catálogo exige um controle com dois handles (mínimo e máximo) que atualiza a URL ao ser solto. O projeto já inclui `@base-ui/react@^1.6.0` como dependência de UI. As opções avaliadas foram: usar o `Slider` do `@base-ui/react`, dois `<input type="range">` nativos sobrepostos via CSS, ou dois inputs numéricos texto.

## Decisão

Usar o componente `Slider` do `@base-ui/react` com `value` como array de dois elementos (range mode). O componente é acessível por padrão (ARIA `role="slider"`, keyboard navigation), estilizável inteiramente com Tailwind via classes nos sub-componentes (`Slider.Root`, `Slider.Track`, `Slider.Indicator`, `Slider.Thumb`), e não adiciona nenhuma nova dependência ao projeto.

O componente `PriceFilter` será um Client Component (`'use client'`) que mantém estado local do par `[min, max]` durante o arrasto e chama `useRouter().push()` com os searchParams atualizados ao disparar o evento `onValueCommitted` (quando o usuário solta o handle).

## Alternativas Consideradas

### Alternativa B: Dois inputs type=range nativos sobrepostos

- **Descrição**: Dois `<input type="range">` com posicionamento absoluto sobrepostos para simular um range dual.
- **Prós**: Zero dependência extra; HTML nativo.
- **Contras**: Requer CSS hack para sobreposição e lógica manual de colisão entre handles; acessibilidade precária sem trabalho extra; visual inconsistente entre browsers.
- **Por que rejeitada**: `@base-ui/react` já está instalado e resolve todos esses problemas.

### Alternativa C: Inputs numéricos texto min/max

- **Descrição**: Dois campos `<input type="number">` com botão "Aplicar".
- **Prós**: Implementação trivial; sem dependência de componente externo.
- **Contras**: Experiência de UX inferior ao slider acordado no PRD; não permite visualização da faixa selecionada.
- **Por que rejeitada**: O PRD definiu explicitamente slider com dois handles.

## Consequências

### Positivas

- Sem nova dependência (`@base-ui/react` já presente).
- Acessibilidade ARIA incluída automaticamente.
- Estilização 100% com Tailwind, consistente com o design system atual.
- `onValueCommitted` garante que a URL só atualiza quando o usuário solta o handle, evitando excesso de navegações.

### Negativas

- `PriceFilter` deve ser Client Component por precisar de estado local de arrasto.
- Produtos com `price = null` (sob consulta) precisam de tratamento explícito — aparecem após os produtos com preço ou são excluídos quando o filtro de preço está ativo.

### Riscos

- A API do `@base-ui/react` Slider pode mudar em versões minor. Mitigação: fixar `^1.6.0` no `package.json` e revisar ao atualizar a lib.
