# ADR-002: Validação de variáveis de ambiente via instrumentation.ts + lib/env.ts

## Status

Aceito

## Data

2026-07-17

## Contexto

O projeto acessa `process.env.*` diretamente em pelo menos 13 pontos distintos espalhados por actions, components, lib e app. Não existe validação centralizada. Variáveis ausentes causam falhas em runtime com mensagens genéricas do JavaScript, sem indicar qual variável falta ou onde. O objetivo é fazer o servidor falhar antes de aceitar tráfego quando a configuração estiver incompleta.

As opções avaliadas foram: (A) `instrumentation.ts` + `lib/env.ts`, (B) apenas `lib/env.ts` importado nos arquivos que usam env vars, e (C) validação no `next.config.ts`.

## Decisão

Criar dois arquivos:

1. **`lib/env.ts`**: define o schema Zod completo de todas as variáveis de ambiente (server-only e públicas separadas), valida `process.env` e exporta um objeto tipado `env`. Se qualquer variável obrigatória estiver ausente, lança `Error` com a mensagem exata da validação Zod.

2. **`app/instrumentation.ts`**: arquivo especial do Next.js 15 executado antes do registro de qualquer rota. Importa `lib/env.ts` para forçar a validação no boot. Todos os acessos existentes a `process.env.*` no código de servidor são substituídos por `env.*` importado de `lib/env.ts`.

## Alternativas Consideradas

### Alternativa B: lib/env.ts importado nos arquivos consumidores

- **Descrição**: Criar `lib/env.ts` e importar no topo de cada arquivo que usa vars. Sem `instrumentation.ts`.
- **Prós**: Simples; sem arquivo novo de infraestrutura.
- **Contras**: Validação só dispara quando aquele módulo é carregado. Se uma action raramente executada tiver uma var ausente, o erro aparece em runtime durante uma requisição real, não no boot.
- **Por que rejeitada**: Não garante que *todas* as vars são validadas antes de o servidor aceitar tráfego.

### Alternativa C: Validação no next.config.ts

- **Descrição**: Adicionar bloco de validação Zod no `next.config.ts`.
- **Prós**: Fácil de localizar; roda em `next build` e `next dev`.
- **Contras**: Em deploys com `next start` (produção), `next.config.ts` não é reexecutado — a validação não ocorre no startup do servidor em produção.
- **Por que rejeitada**: Não cobre o caso mais crítico (startup de produção).

## Consequências

### Positivas

- Qualquer variável ausente causa falha imediata e descritiva no boot, antes de qualquer requisição ser aceita.
- Código consumidor ganha tipos TypeScript inferidos a partir do schema Zod — elimina necessidade de `!` (non-null assertions).
- Único ponto de verdade para naming e tipagem das variáveis de ambiente.

### Negativas

- Requer substituição de todos os `process.env.*` existentes pelo objeto `env` — mudança de médio alcance.
- Variáveis `NEXT_PUBLIC_*` usadas em Client Components não podem ser lidas do objeto `env` server-only; mantêm `process.env.NEXT_PUBLIC_*` nos componentes client, mas são validadas no schema server-side.

### Riscos

- Se `instrumentation.ts` for desabilitado na config do Next.js (`instrumentationHook: false`), a validação de boot não executa. Mitigação: verificar `next.config.ts` e garantir que `instrumentationHook` está habilitado ou ausente (padrão habilitado no Next.js 15).

## Notas de Implementação

```typescript
// lib/env.ts (estrutura)
import { z } from 'zod'

const serverSchema = z.object({
  DATABASE_URL: z.string().url(),
  RESEND_API_KEY: z.string().min(1),
  UPLOADTHING_TOKEN: z.string().min(1),
  AUTH_SECRET: z.string().min(1),
  R2_ACCOUNT_ID: z.string().min(1),
  R2_ACCESS_KEY_ID: z.string().min(1),
  R2_SECRET_ACCESS_KEY: z.string().min(1),
  R2_BUCKET_NAME: z.string().min(1),
  NEXT_PUBLIC_WHATSAPP_NUMBER: z.string().min(1),
  NEXT_PUBLIC_SITE_URL: z.string().url(),
})

const parsed = serverSchema.safeParse(process.env)
if (!parsed.success) {
  console.error('[Technicfix] Variáveis de ambiente inválidas:', parsed.error.flatten())
  throw new Error('[Technicfix] Configuração de ambiente incompleta. Veja o log acima.')
}
export const env = parsed.data
```

```typescript
// app/instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    await import('../lib/env')
  }
}
```
