# ADR-002: Extrair MobileMenu como Client Component para controle do Sheet

## Status

Aceito

## Data

2026-07-18

## Contexto

O `Header.tsx` é um Server Component e o `Sheet` (drawer mobile) está em modo uncontrolled — sem props `open`/`onOpenChange`. Para fechar o drawer programaticamente após uma busca (F2), é necessário um estado React controlado. O Header não pode ter `'use client'` sem perder o fetch server-side de categorias e produtos. A busca (`HeaderSearchBar`) é Client Component e precisa disparar o fechamento do Sheet.

## Decisão

Criar `components/layout/MobileMenu.tsx` como Client Component (`'use client'`) que encapsula o Sheet, SheetTrigger, SheetContent, HeaderSearchBar, CategoryAccordion e o accordion de Produtos. O `Header` Server Component busca dados e passa `categories` e `products` como props para `MobileMenu`.

## Alternativas Consideradas

### Alternativa A: Converter Header inteiro para Client Component

- **Descrição**: Adicionar `'use client'` ao Header, fazer fetches client-side (useEffect/SWR).
- **Prós**: Implementação mais simples, um único arquivo.
- **Contras**: Header aparece em todas as páginas públicas — fetch client-side cria loading states visíveis; perde RSC streaming; performance degradada.
- **Por que rejeitada**: Impacto de performance inaceitável para um componente presente em 100% das páginas.

### Alternativa B: Context/EventEmitter global para fechar Sheet

- **Descrição**: Criar um contexto React que expõe `closeMenu()`; HeaderSearchBar chama esse contexto ao submeter.
- **Prós**: Desacoplamento.
- **Contras**: Over-engineering — adiciona indireção sem benefício real para um caso simples de prop callback.
- **Por que rejeitada**: YAGNI.

## Consequências

### Positivas

- Header mantém fetch server-side (categorias e produtos buscados no servidor, sem latência visível).
- MobileMenu tem controle total do Sheet via `useState<boolean>`.
- HeaderSearchBar recebe `onSearch?: () => void` e chama após `router.push`.

### Negativas

- Header passa a aceitar `categories` e `products` como props (quebra a assinatura atual sem props).
- Dois arquivos para manter em vez de um (Header + MobileMenu).

### Riscos

- `HeaderSearchBar` atualmente não tem prop `onSearch` — requer adição de prop opcional para não quebrar usos existentes.

export async function Header() {
  const [categories, products] = await Promise.all([
    getCategoriesForNav(),
    getProductsForNav(),
  ])
  return (
    <header ...>
      {/* Camada 1 TopBar */}
      {/* Camada 2 MainBar com HeaderSearchBar desktop */}
      <MobileMenu categories={categories} products={products} />
    </header>
  )
}
