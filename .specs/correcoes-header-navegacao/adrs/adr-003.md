# ADR-003: ProductsDropdown com React state hover, consistente com CategoryNav

## Status

Aceito

## Data

2026-07-18

## Contexto

O item "Produtos" no Header precisa de um dropdown desktop que lista até 30 produtos A–Z + link "Ver todos". O CategoryNav existente (desktop) já usa `useState<string | null>` + `onMouseEnter`/`onMouseLeave` para controlar hover. Precisamos decidir se o novo dropdown segue o mesmo padrão ou adota CSS puro.

## Decisão

Criar `components/layout/ProductsDropdown.tsx` como Client Component usando o mesmo padrão de React state (`useState<boolean>` para `isOpen`) + `onMouseEnter`/`onMouseLeave`, idêntico ao comportamento visual do CategoryNav. O componente recebe `products: ProductNavItem[]` como prop.

## Alternativas Consideradas

### Alternativa A: CSS puro com `:hover` / Tailwind `group`

- **Descrição**: Usar `group-hover:block` / `group-hover:flex` no Tailwind, zero JS.
- **Prós**: Sem hidratação, mais simples.
- **Contras**: Comportamento inconsistente em tablets (touch não dispara `:hover`); não suporta lógica de delay para evitar fechamento acidental; não alinha com o padrão já estabelecido pelo CategoryNav.
- **Por que rejeitada**: Inconsistência visual e funcional com CategoryNav; problemas conhecidos em touch devices.

## Consequências

### Positivas

- Comportamento idêntico ao CategoryNav — experiência consistente para o visitante.
- Facilita futuros ajustes (delay de hover, click fora para fechar) usando o mesmo padrão.

### Negativas

- Requer hidratação client-side para o dropdown de Produtos.

### Riscos

- Nenhum risco significativo; padrão já validado pelo CategoryNav existente.

## Notas de Implementação

```tsx
// Interface de dados para o dropdown
interface ProductNavItem {
  name: string
  slug: string
}

// ProductsDropdown aceita products: ProductNavItem[]
// Renderiza no desktop (hidden md:block) com hover state
// No mobile, o accordion é tratado dentro do MobileMenu
```
