# ADR-001: Integrar CategoryNav existente ao Header em vez de criar NavBar do zero

## Status

Aceito

## Data

2026-07-18

## Contexto

O Header atual (Server Component, 2 camadas) não monta o `CategoryNav.tsx` existente nem expõe itens de navegação para Categorias e Produtos. O componente `CategoryNav` já implementa mega-menu hierárquico no desktop e accordion com `<details>/<summary>` no mobile, consumindo uma prop `categories: CategorySummary[]`. A alternativa seria criar uma `NavBar` unificada do zero absorvendo CategoryNav.

## Decisão

Integrar o `CategoryNav.tsx` existente como nova camada de navegação no Header e criar um `ProductsDropdown` análogo para o item "Produtos" (máx. 30 itens A–Z + link "Ver todos"). O fetch de categorias e produtos ocorre no Server Component pai e os dados são passados como props.

## Alternativas Consideradas

### Alternativa A: Nova NavBar unificada do zero

- **Descrição**: Criar componente `NavBar` que absorve Categorias e Produtos em uma única árvore nova, descontinuando CategoryNav.
- **Prós**: Arquitetura limpa, controle total sobre layout e animações.
- **Contras**: Maior escopo; descarta código funcional; risco de regressão na navegação existente.
- **Por que rejeitada**: Custo/benefício desfavorável — CategoryNav já resolve o problema de hierarquia e mobile.

## Consequências

### Positivas

- Reutiliza código existente testado visualmente.
- Menor superfície de mudança no Header.
- CategoryAccordion pode ser injetado no Sheet mobile com prop `variant='light'` já disponível.

### Negativas

- Header precisa receber dados (categorias + produtos) via props ou o PublicLayout precisa fazer os fetches.
- Adiciona uma terceira camada visual ao Header já existente.

### Riscos

- Fetch de produtos no Server Component de layout pode aumentar latência inicial da página; mitigar com `Promise.all` paralelo.

## Referências

- `components/layout/CategoryNav.tsx` — componente existente a ser integrado
- `components/layout/Header.tsx` — componente a ser estendido
